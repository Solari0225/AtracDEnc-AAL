# AtracDEnc-AAL 0.5.0

基于 AtracDEnc 的独立 AAL 编解码器，提供 Windows/macOS 中英文自适应简易测试转换器、命令行、C API 和完整源码。此版本保持实验版标识。

An independent AtracDEnc-based AAL codec with bilingual native Windows/macOS test converters, CLI, C API and complete source. This remains an experimental release.

## 本次更新 / Changes

- **移除固定 1 GiB 上限**，CLI/GUI 改为有界缓冲、按帧连续编解码。**No fixed 1 GiB cap**; bounded frame-by-frame file conversion.
- 保留原压缩方法，编码逐包独立解码并逐样本校验，SHA-256 增量计算。Existing compression is retained, with independent per-packet PCM verification and incremental SHA-256.
- 新增 `aal_encode_cd16_stream` / `aal_decode_cd16_stream` 回调 C API，旧整缓冲 ABI 保留。New callback C APIs preserve the whole-buffer ABI.
- 支持 RIFF/RF64 输入；大 WAV 输出自动使用 RF64，64 位计数并拒绝容器字段溢出。RIFF/RF64 input, automatic RF64 output and checked 64-bit counters.

## 下载 / Downloads

- Windows x64：解压打开 `AtracDEnc-AAL-GUI.exe`，同包有 CLI 和库。Extract the native test GUI, CLI and static library.
- macOS universal：`AtracDEnc-AAL-GUI.app` 与 CLI，Apple Silicon / Intel，macOS 11+。The app is ad-hoc signed, without Developer ID or notarization.
- Source ZIP：完整源码、许可证、文档、回归与离线夹具。Complete source, licenses, documentation and offline tests.
- `SHA256SUMS.txt` 与 `RELEASE-VALIDATION.json`：附件摘要、源提交、三平台实际测试和大文件/RSS 数据。Asset hashes, exact source and observed native/large-file/memory results.

## 输入要求 / Required inputs

**编码：44,100 Hz / signed 16-bit / 双声道整数 PCM WAV（RIFF 或 RF64，format tag 1）。** 无自动重采样、位深转换或混音。24/32-bit、浮点、单声道、多声道及其他采样率直接拒绝。

**Encode: 44,100 Hz / signed 16-bit / stereo integer PCM WAV (RIFF or RF64, format tag 1).** No automatic resampling, bit-depth conversion or downmixing; unsupported specifications are rejected.

**解码：未加密 AAL3/AALP OMA/AA3，已验证十档配置。** 精确保留 PCM 长度，输出 RIFF WAV 或大文件 RF64。MP3/FLAC 等不是直接输入。旧整缓冲 C API 仍需容纳完整结果的内存；文件流程和新回调接口才提供有界工作内存。容量还受容器字段、文件系统和磁盘约束。见 [输入规格](../INPUT-FORMATS.md) 与 [流式设计/接口](../STREAMING.md)。

**Decode: unencrypted AAL3/AALP OMA/AA3 in the ten supported profiles.** Output preserves exact PCM length, using RIFF or RF64 as needed. MP3/FLAC are not direct inputs. Whole-buffer APIs still require complete-result memory; file and callback paths provide bounded codec buffers. Container fields, filesystem and disk constraints remain. See [input requirements](../INPUT-FORMATS.md) and [streaming](../STREAMING.md).

## 验证与边界 / Validation and limits

发布要求 Windows x64、macOS arm64、macOS Intel 原生九项无窗口检查，包括十档 70 项 0.4.0 完整 AAL 摘要回归；各平台另执行真实大于 1 GiB 的输入 PCM、AAL 和还原 PCM 往返，长度/摘要一致，峰值 CLI 工作集/RSS ≤64 MiB。最终 Mac 通用程序再次检查架构、签名并执行无窗口诊断。实际数值与源码提交见附件记录。

Publication requires nine headless checks on all three native platforms, including 70 frozen complete-AAL regressions, plus real >1 GiB PCM/AAL/PCM round trips with exact length/hash and peak CLI working set/RSS ≤64 MiB. The final universal Mac binaries are architecture/signature checked and executed headlessly. Attached records contain actual measurements and exact source.

大文件测试阈值不是所有环境或 GUI 的内存保证。RF64 >4 GiB 有长度字段边界检查，小 RF64 有完整往返；本轮完整大文件验收约 1 GiB。Sony 双向 PCM 对照和现有算法范围见仓库验证资料；本次没有实现 Sony 原版全部编码决策，不保证与 Sony 完整文件字节或体积相同。

The memory test threshold is not a universal GUI/system guarantee. RF64 >4 GiB fields have boundary checks and small RF64 files have full round trips; current complete large-file acceptance is about 1 GiB. Sony reference/algorithm scope is documented in the repository. Full Sony encoding decisions are not newly implemented, and complete bytes/sizes can still differ.

**仅 High-Speed Transfer；Standard 未实现，目前无已核验证据证明 RFC 定义的 Standard 曾在实际产品或服务中应用。** GUI 视觉交互由用户测试，Walkman 实机播放、跳转和传输仍未验证。见 [模式与来源](../AAL-MODES.md)。

**High-Speed Transfer only. Standard remains unsupported, with no acquired verified evidence of RFC-defined Standard product/service deployment.** GUI interaction is tested by the user; physical Walkman playback, seeking and transfer remain unverified. See [modes/evidence](../AAL-MODES.md).
